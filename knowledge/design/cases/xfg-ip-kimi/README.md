# Case · xfg-ip-kimi(小飞棍 IP 设计案例)

> `design.cases.xfg-ip-kimi` · 仅作真实产出反例与正例的来源,不进入通用方法论。
> 本目录的项目专属词(讯飞、小飞棍、效率权杖、深空灰等)被结构测试限定**只能在此**出现。

## 案例定位

历史项目"小飞棍"(企业效率场景型 IP)的真实产出。它在两点上比常规版本走得更远,值得作为通用方法论的样例参考:

1. **提示词系统更精细**:四层结构 + 量化锁定 + 严格避免项 + 状态延展。
2. **状态延展更体系**:多状态序列(待机/激活/执行/确认/完成/失败)且与情绪表达对齐。

## 文件清单

- `before-after-and-pitfalls.md`:跑偏与改写对照,聚焦提示词、状态、识别度。
- `gap-report-sample.md`:含临时放行边界的 gap 报告样例。
- `notes.md`:阅读引导与项目专属词提醒。

## 阅读引导

- 通用方法论决定"该做什么 / 怎么判断好坏",本案例展示"在企业效率场景型 IP(无传统文化原型)落地时,如何通过提示词与状态延展锁定一致性"。
- 项目专属符号(效率权杖、五域体系、点挥即成动效)只能停在 cases。
- 这个案例可对照 `design.cases.xfx-ipdesign` 看两种不同文化原型(武侠 vs 企业效率)在通用方法论下的落地差异。
