# 信息架构方法（Information Architecture）

> 通用资产 · `product.information-architecture` · status: draft
> 页面/导航/命名的通用信息架构方法。本文只给组织原则与命名约定,不含任何
> 具体产品的页面树;不规定路由实现,不绑定前端框架。

## 组织原则

- **页面 = 信息消费单元**:用户在一个入口内完成一个或一组目标。
- **就近聚合**:相关信息聚在一起,跨目标的信息分页承载。
- **导航反映心智**:导航结构对应用户的任务心智,而非后端模块划分。
- **深度可控**:常用目标的到达深度尽量浅。

## 页面类型口径

通用枚举:list / form / detail / dashboard / wizard / settings / auth / error。每个页面应能归入其一,归不进说明边界不清,需重新拆。

## 命名约定

- 资源集合用复数名词(`/rules` 而非 `/rule-list`)。
- 动词不进路径;动作由页面内交互承载。
- 命名稳定、可预测,同类资源命名风格一致。

## 适用边界

本文给组织与命名原则;具体页面树、路由实现、框架选择由消费方 skill 决定。
