# DesignOS UXEval — 设计师内测指南

> 给团队内部设计师，**3 步上手，不碰命令行**

---

## 一、一次性准备（5 分钟）

### 1. 下载 DesignOS

```bash
git clone git@github.com:Eryooo/designos.git ~/Documents/designos
```

不会用 git？直接在浏览器打开 https://github.com/Eryooo/designos ，点 `Code` → `Download ZIP`，解压到 `~/Documents/designos`。

### 2. 用 IDE 打开它

在你常用的 IDE 里打开 `~/Documents/designos` 目录：

- **Trae** / **Claude Code** / **Cursor** / **Codex** / **Workbuddy** / **Codebuddy** 都可以
- IDE 会自动读 `AGENTS.md`，识别 DesignOS 能力

### 3. 完成

**不用装 Python，不用 pip install，不用配 API Key。**

IDE 里你已经配过的 Claude / GPT 模型就是 DesignOS 用的模型。

---

## 二、做一次体验评估

### 第 1 步：建项目子目录

在 `~/Documents/designos/work/` 下建一个新目录，丢进 PRD：

```
~/Documents/designos/work/新版工作台评估/
├── prd.md           ← 你的 PRD（任意格式：.md / .pdf / .docx）
└── screens/         ← 产品截图（可选，5+ 张关键页面）
    ├── 01-登录.png
    ├── 02-首页.png
    └── ...
```

### 第 2 步：对 IDE 里的 AI 说一句话

进入 `work/新版工作台评估/` 目录，对 AI 说：

> **`/uxeval`**

或更详细：

> 「请用 uxeval skill 评估当前目录的产品」

### 第 3 步：跟着对话走

AI 会自动按 12 阶段执行（约 6-8 分钟）：

1. 读 PRD → 推断评估范围（让你审阅 `scope.md`）
2. 推导用户角色 → 场景 → 旅程图 → **暂停问你「旅程对吗？」**
3. 生成体验任务清单 → **暂停问你「任务清单对吗？」**
4. 截图分析 → 启发式检测 → 问题归因 → **暂停问你「严重等级对吗？」**
5. 输出 Excel 报告

**三个暂停点**回复 `继续` / `修改 <说明>` / `补充` 即可。

---

## 三、产出物

每次跑完，在 `work/<项目名>/runs/<run-id>/outputs/` 下：

| 文件 | 内容 |
|---|---|
| `旅程地图.md` | 用户旅程图 + 阶段表 |
| `任务清单-完整版.md` | 完整体验任务（给资深设计师） |
| `任务清单-简洁版.md` | 简版（给中阶设计师顺序执行） |
| `问题清单.md` | Markdown 问题清单（含严重等级 + 证据 + 建议） |
| `evidence/` | 截图证据 |
| `<时间戳>.xlsx` | Excel 报告（给产品/研发分派） |

## 四、常见问题

### 1. AI 在 IDE 里没识别 `/uxeval`？

确认你打开的是 `~/Documents/designos` 目录（含 `AGENTS.md`）。
如果在子目录打开，把 `AGENTS.md` 复制一份到子目录。

### 2. 跑到中间断了

对 AI 说：「继续刚才的评估」或 `/uxeval resume`。

### 3. 评估方向跑偏（变成功能测试）

在 Checkpoint 时回复「修改」，告诉 AI：
> 「目前的任务清单偏功能测试了，请按"用户能否完成 XX 任务"重写」

### 4. 截图没法提供（客户端登录不了）

写一份 `screens-description.md`，文字描述每个页面。AI 会把它当虚拟截图处理。

```markdown
### 工作台-首页
- 顶部导航：Logo / 工作台 / 数据治理 / 设置
- 左侧侧边栏：3 级菜单
- 主区域：12 条待办（无视觉分类）
- 痛点：信息过载，无法快速定位
```

### 5. 我没有 Claude 账号 / IDE 用的是 GPT，能跑吗？

可以。`/uxeval` 流程用的就是 IDE 自身配置的模型。
**注意**：12 阶段 prompt 都针对 Claude 调优过，GPT-4o / DeepSeek 跑出来质量可能下降 20-30%。
推荐用 Claude Opus / Sonnet。

### 6. PRD 是 PDF / Word，能直接读吗？

可以。AI 会调用 IDE 自带的文件读取能力解析。
极端情况（扫描版 PDF）建议先用工具转成文字。

## 五、给工程师 / 批量评估（可选）

如果你要在 CI 里批量跑、或者想自动化产出报告，可以装 Python 包：

```bash
pip3 install designos
designos run uxeval --mode client --workspace ./my-project
```

详见 `docs/developer-guide.md`。**设计师用 IDE 模式即可，不需要走这条路径。**

## 六、内测反馈

跑完后把以下信息发给 young：

1. **耗时**：哪个 stage 最慢？
2. **质量**：哪个 stage 的输出不够好？（贴原文）
3. **跑偏**：有没有出现「功能测试式」问题？
4. **缺失**：还缺什么输入字段 / 输出产物？
5. **使用流畅度**：哪一步卡住了？

反馈直接发到团队群或 GitHub Issue。
