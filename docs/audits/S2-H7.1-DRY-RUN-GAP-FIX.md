# S2-H7.1 Dry-Run Gap Fix

**批次**: S2-H7.1
**时间**: 2026-06-15
**状态**: COMPLETED

---

## 1. 背景

S2-H7B Offline Dry-Run Execution 证明了外部 workspace 隔离机制和四大质量门(H5/H5.1/H6/H4)串联可执行，但暴露了 4 个机制缺口：

1. **Input gate 缺少"推荐补充字段清单"**
2. **Progressive checkpoint 缺少"降级范围明细"**
3. **Consistency gate 缺少"推荐 reconcile 方案"**
4. **Diagnostic summary 缺少"KR 聚合视图"**

本批目标：修复这 4 个机制问题，让用户和维护者看到问题时，不只知道"有问题"，还知道：
- 缺什么
- 该补什么
- 如果继续会降级哪里
- 冲突该如何裁定
- 哪些 KR 被影响
- 应该修哪个主项目位置

---

## 2. 四个机制问题的用户影响

### 问题 1: Input gate 只提示缺口，不推荐补什么

**用户痛点**:
- 看到 `needs_user_clarification` 但不知道该补哪些字段
- 不知道哪些字段是 blocker，哪些可以带 assumption 继续

**影响**:
- 用户反复试错，补了不重要的字段，遗漏关键字段
- 无法快速决策"是继续还是暂停"

### 问题 2: Checkpoint 只说降级，不说具体降了什么

**用户痛点**:
- 看到 `degrade_scope` 但不知道具体影响哪些产出
- 不知道降级后的质量变化是否可接受

**影响**:
- 用户无法判断降级范围是否超出可接受边界
- 交付后才发现关键功能被降级

### 问题 3: Consistency gate 只提示冲突，不给裁定方案

**用户痛点**:
- 看到 `needs_reconciliation` 但不知道该选哪个版本
- 不知道冲突的利弊权衡

**影响**:
- 用户被迫自己推理裁定逻辑，可能选错
- 下游静默覆盖上游，丢失一致性

### 问题 4: Diagnostic summary 只列 KR，不聚合状态

**用户痛点**:
- 看到 linked_kr 列表但不知道哪些 pass、哪些 fail
- 不知道哪些 KR 受影响最大

**影响**:
- 维护者无法快速定位"最该修的 KR"
- 无法追踪质量门整体通过率

**新增字段**:
- `recommended_reconciliation` — 推荐的裁定方式
- `reconciliation_options` — 可选方案清单（至少 2 个）
- `preferred_resolution` — 推荐方案及理由
- `user_confirmation_needed` — 是否需要用户确认

**示例**:
```markdown
### Reconciliation Options (S2-H7.1)

| option_id | resolution_approach | pros | cons | user_action_needed |
|---|---|---|---|---|
| OPT-1 | 以上游为准 | 保持上游一致性 | 下游需修改已推断字段 | no (自动修正) |
| OPT-2 | 以下游为准 | 保持下游已有逻辑 | 可能与上游设计意图不一致 | yes (需用户确认偏离) |
| OPT-3 | 追问用户裁定 | 由用户明确决策 | 需要用户介入 | yes |

**推荐方案**: OPT-1 (以上游为准)
**理由**: 上游 skill 产出应作为下游输入的权威来源。
```

## 4. 修复方式

### 修复原则

1. **不强迫用户补充所有字段** — 只列对质量影响最大的字段
2. **不只提示问题，必须给方案** — 至少 2 个可选裁定方案
3. **不降低透明度** — 降级必须说明具体降了什么
4. **不假装 KR 状态** — unknown 就标 unknown，不允许假装 pass

### 实施方式

- 在 5 个 skill 的 input-quality-gate 模板中增加 3 个子章节
- 在 5 个 skill 的 progressive-quality-checkpoints 模板中增加 4 个字段（每个 checkpoint 记录）
- 在全局 cross-skill-consistency-review 模板中增加 reconciliation options 章节
- 在 5 个 cross-skill contract 中增加具体场景的 reconciliation 方案
- 在 diagnostic-summary 模板和 schema 中增加 KR aggregation 结构

### 校验脚本更新

- `scripts/validate_input_quality_templates.py` — 检查 recommended_missing_fields / recommended_user_questions / minimum_needed_to_continue
- `scripts/validate_progressive_quality_checkpoints.py` — 检查 degradation_scope_detail / affected_outputs / user_visible_impact / continue_conditions
- `scripts/validate_cross_skill_consistency_contracts.py` — 检查 recommended_reconciliation / reconciliation_options / preferred_resolution / user_confirmation_needed
- `scripts/validate_feedback_safety_infrastructure.py` — 检查 kr_summary / affected_kr / most_affected_kr

## 8. 从产品视角说明：H7.1 如何让用户/维护者知道"下一步该做什么"

### 用户视角

#### 场景 1: Input gate 提示 `needs_user_clarification`

**H7B 之前**:
```
input_decision: needs_user_clarification
rationale: PRD 缺少成功指标
```
用户看到后：❓ "我该补什么？"

**H7.1 之后**:
```
input_decision: needs_user_clarification

推荐补充字段：
1. business_goal（明确的业务目标，至少一句话目标） — blocker
2. competitor_list（3-5 个竞品清单，至少 3 个） — blocker
3. user_research（用户访谈数据，可带 assumption） — major

推荐问题：
- 本次设计的核心目标 KPI 是什么？（blocker）
- 主要竞品有哪些（至少 3 个）？（blocker）
```
用户看到后：✅ "我先补 business_goal 和 competitor_list，user_research 如果没有可以标 assumption"

#### 场景 2: Checkpoint 提示 `degrade_scope`

**H7B 之前**:
```
checkpoint_decision: degrade_scope
```
用户看到后：❓ "降级了什么？我还能用吗？"

**H7.1 之后**:
```
checkpoint_decision: degrade_scope

降级范围明细：
- 本次降级：仅覆盖主流程，不含错误/加载/空状态
- 受影响产出：verified_issues 数量 -30%，unverified_issues +10%
- 用户可见影响：看不到边界场景问题，主流程问题仍完整
- 继续条件：用户明确接受"仅主流程覆盖"，或后续补充边界场景截图
```
用户看到后：✅ "主流程问题没丢，边界场景可以后补，可以继续"

#### 场景 3: Consistency gate 提示 `needs_reconciliation`

**H7B 之前**:
```
consistency_decision: needs_reconciliation
conflict: target_audience 不一致（ai-analytics 说 5-20 人，prd2proto 说 10-50 人）
```
用户看到后：❓ "我该选哪个？"

**H7.1 之后**:
```
consistency_decision: needs_reconciliation

裁定方案：
- OPT-1: 以 ai-analytics 为准（推荐） — 保持分析结论一致性
- OPT-2: 以 prd2proto 为准 — 保持 PRD 原始意图，需确认偏离
- OPT-3: 追问用户明确目标用户 — 由用户给出权威输入

推荐方案：OPT-1
理由：ai-analytics 基于用户调研，应作为权威来源
```
用户看到后：✅ "选 OPT-1，以 ai-analytics 为准"
