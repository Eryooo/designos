# S2-H5.1 — Progressive Quality Checkpoints

> **本报告性质**:执行中渐进质量检查点规范。**引用层 / 检查点规范层,非新标准层**——不新增 KR / failure mode / rubric / shared knowledge 真源,不改 runtime / pipeline / factory / release。
> **核心产品价值**:不让用户跑几小时后才在最后 H4 被告知"质量不合格"。执行中分阶段早发现、早告知、早降级、早阻断。
> **日期**:2026-06-12

---

## 1. 为什么需要 H5.1

| 阶段 | 已有 gate | 解决的问题 | 缺口 |
|---|---|---|---|
| 执行前 | **S2-H5 Input Quality Gate** | 输入是否足够支撑产出 | 只看起点 |
| 执行后 | **S2-H4 Self Review Gate** | 最终输出是否可交付 | 只看终点 |
| **执行中** | ❌(本批补) | **质量演进:能否继续 / 是否追问 / 是否降级** | **此前完全空白** |

**糟糕体验**:用户提交输入(H5 ready)→ 跑完 18 stage / 6 阶段(数小时)→ H4 突然 block → 用户白等。
**H5.1 修复**:把检查点插进执行过程,问题在第 2 步就被发现并告知,而非第 18 步。

---

## 2. 三门协同关系

| Gate | 时机 | 判断 | 决策枚举 |
|---|---|---|---|
| **H5 Input Quality Gate** | 执行**前** | 能不能开始 | ready / ready_with_assumptions / needs_user_clarification / blocked_insufficient_input |
| **H5.1 Progressive Checkpoints**(本批) | 执行**中** | 能不能继续 / 是否追问 / 是否降级 | continue / continue_with_gaps / ask_user / degrade_scope / stop_blocked |
| **H4 Self Review Gate** | 交付**前** | 能不能交付 | pass / pass_with_minor_warnings / degrade_with_gaps / block |

三门职责不重叠:**起点 → 过程 → 终点**,各自有可对账的判定。

---

## 3. 五大产品原则

| 原则 | 含义 | 对应 checkpoint_decision |
|---|---|---|
| **Fail early** | 明显无法满足交付标准时尽早阻断 | stop_blocked |
| **Degrade progressively** | 可继续但质量不足时尽早降级范围(而非最后才降) | degrade_scope |
| **Ask when useful** | 少量追问能显著提升质量时及时追问 | ask_user |
| **Carry gaps forward** | 允许带 gap 继续,但必须持续携带 + 最终显式呈现 | continue_with_gaps |
| **No surprise block** | H4 不应突然出现前面完全没提示过的 blocker(除非是最后阶段才可发现) | (检查点日志保证 H4 可追溯) |

---

## 4. checkpoint_decision 枚举

### 4.1 唯一枚举(只允许这 5 个)
```
continue
continue_with_gaps
ask_user
degrade_scope
stop_blocked
```

### 4.2 判定逻辑(优先级从高到低)

| 优先级 | 条件 | checkpoint_decision |
|---|---|---|
| 1(最高) | 命中 **blocker FM**,且无法在当前阶段修复 | **stop_blocked** |
| 2 | 命中 **blocker FM**,但可通过用户补充关键输入解决 | **ask_user** |
| 3 | 命中 **major FM**,且继续会影响关键产出 | **degrade_scope** |
| 4 | 存在 **gap/assumption**,但不阻断核心产出 | **continue_with_gaps** |
| 5 | 无关键风险 | **continue** |

> 与 H4 对偶:stop_blocked → H4 必然 block;degrade_scope → H4 可能 degrade_with_gaps;continue_with_gaps → H4 检查 gap 标注覆盖率。

## 5. 通用 checkpoint 结构

每个 checkpoint 必含:

| 字段 | 含义 |
|---|---|
| checkpoint_id | CP-{P/U/A/I/B}{n} |
| stage_or_phase | 对应执行阶段 |
| expected_intermediate_artifact | 该阶段应产出的中间产物 |
| required_evidence | 判定所需证据 |
| related_kr | 引用 S2-H1.1 KR 编号 |
| related_failure_modes | 引用 S2-H3 FM id(不复制正文) |
| quality_probe_questions | 该检查点的质量探针问题 |
| detected_gaps | 检测到的缺口 |
| checkpoint_decision | §4 五枚举之一 |
| user_notice | 非 continue 决策的用户可读说明 |
| carry_forward_items | 带入后续阶段的 gap/assumption |

---

## 6. 用户通知原则

每个**非 continue** 决策必须生成用户可读说明,含 5 项:

| 通知项 | 内容 |
|---|---|
| **当前发现了什么** | 检测到的具体 gap / FM 命中 |
| **对最终质量有什么影响** | 影响哪个产出 / KR |
| **用户可以补什么** | 具体可补充的输入(对应 ask_user) |
| **如果继续会以什么降级方式交付** | degrade_scope 的范围说明 |
| **是否需要用户确认** | yes / no |

> 禁止:静默继续、把决策埋进日志不告知用户。

## 8. 与 H4 / H5 的衔接

| 衔接 | 规则 |
|---|---|
| H5 → H5.1 | H5 输出的 gaps / assumptions,H5.1 在 checkpoint 中**持续携带**(carry_forward_items) |
| H5.1 → H4 | H5.1 输出 **checkpoint log**,H4 **必须读取**(self-review gate §7 检查 H5.1 携带的 gap 是否被标注) |
| H4 block 的可追溯性 | H4 若 block,**必须能追溯到 H5 / H5.1 哪一步已有预警**;否则在 H4 标记为 **late-discovered-risk**(仅限最后阶段才可发现的问题,如 code-generation 才暴露的约束冲突) |

```
H5 input gate          H5.1 checkpoints              H4 self review
─────────────          ──────────────────           ──────────────
ready/...        →     CP1 → CP2 → ... → CP5    →    pass/block/...
gaps/assumptions  ───────► carry forward ──────────► 检查标注覆盖
                       checkpoint log    ──────────► 追溯预警来源
```

## 9. 明确不可做

- ❌ 不在 H5.1 中新增质量标准(只引用 H1~H4)
- ❌ 不让 checkpoint 变成形式主义日志(每个非 continue 决策必须有真实 user_notice)
- ❌ 不把 checkpoint 结果伪装成真实验证(checkpoint 是过程探针,非 validated 证据)
- ❌ 不跳过用户通知(No surprise block 原则)
- ❌ 不用真实业务数据做示例(synthetic / sanitized only)

## 11. 产品视角:H5.1 如何避免"跑很久最后才被拒绝"

| 时间点 | 无 H5.1(旧) | 有 H5.1(本批) |
|---|---|---|
| T+2min(CP-P1) | 静默继续 | 检测输入缺业务目标 → **ask_user**,立即追问 |
| T+10min(CP-P3) | 静默继续 | 策略链不成立 → **degrade_scope**,告知将降级范围 |
| T+30min(CP-P5) | 静默继续 | 代码宪法风险 → **stop_blocked** 或带 gap 继续(已提前告知) |
| T+2h(H4) | **突然 block,白等 2 小时** | H4 决策**全部可追溯到前面 checkpoint 预警**,无惊吓 |

核心:把"最后一刻的 block"分散成"过程中的多次早期提示",用户在第一个检查点就能选择追问/降级/停止,不浪费后续时间。
